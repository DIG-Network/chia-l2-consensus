# RPC-006 — Dependency Version Alignment

> **Authoritative requirement:** [RPC-006](../NORMATIVE.md#RPC-006)
> **Verification:** [VERIFICATION.md](../VERIFICATION.md)
> **Tracking:** [TRACKING.yaml](../TRACKING.yaml)

## Summary

Adding `chia-query` and `dig-wallet-backend` requires aligning the Chia ecosystem
crate versions. Both upstream crates use newer versions of `chia-wallet-sdk`
and related crates than our project currently uses. Types from these crates
(e.g., `Coin`, `Bytes32`, `SpendBundle`) must be the same type across crate
boundaries to avoid compilation errors.

## Specification

### Current Dependencies

| Crate | Current Version | Used By |
|-------|----------------|---------|
| `chia-wallet-sdk` | 0.34 | SpendContext, Launcher, singleton drivers |
| `chia-protocol` | 0.36 | Bytes32, Coin, SpendBundle |
| `chia-puzzles` | 0.20 | compiled singleton_top_layer_v1_1 and its hash |
| `chia-puzzle-types` | 0.36 | SingletonArgs, SingletonSolution, Proof |
| `chia-bls` | 0.36 | BLS aggregate signatures |
| `clvm-traits` | 0.36 | CLVM serialization |
| `clvm-utils` | 0.36 | curry_tree_hash |
| `clvmr` | 0.16 | CLVM runtime |

`chia-puzzles` 0.20 carries only the compiled puzzles and their hashes. The
Rust argument and solution types it previously held now live in
`chia-puzzle-types`, so both crates are required.

### Upstream Versions (as SHIPPED — dig-wallet-backend, not dig-l1-wallet)

`dig-l1-wallet` was REPLACED by `dig-wallet-backend`, and `tests/vv_req_rpc_006.rs:42`
asserts `dig-l1-wallet` is not a dependency of this crate. It is signing-capable, so
re-adopting it would cross the boundary CLAUDE.md §908 exists to hold. The rows below
are the versions this crate actually resolves.

| Crate | Version |
|-------|---------|
| `chia-wallet-sdk` | 0.34 |
| `clvm-traits` / `clvm-utils` | 0.36 |
| `clvmr` | 0.16 |
| `chia-query` | 0.12 |
| `dig-wallet-backend` | 0.27 (`default-features = false`, `features = ["engine"]`) |

There is NO `chia` umbrella row, and that is deliberate: the umbrella crate has no 0.36
line (it goes 0.32 → 0.42), so a crate on the 0.36 chain names the direct facades
instead. Note `chia::puzzles` meant `chia_puzzle_types`, NOT the separate `chia-puzzles`
crate — both resolve in the same lock, so that is the rename that silently compiles to
the wrong item.

### Target Cargo.toml

```toml

# facades are named instead. `chia::puzzles` meant `chia-puzzle-types`, NOT the
# separate `chia-puzzles` crate, which kept only the compiled puzzles at 0.20.
chia-wallet-sdk  = "0.34"
```

### Breaking Changes to Handle

The version bump from `chia-wallet-sdk 0.18` → `0.30` will likely introduce
API changes. Common areas:

| Area | Likely Changes |
|------|---------------|
| `SpendContext` | Method signatures may differ |
| `Launcher` | Singleton creation API may change |
| `CurriedProgram` | Currying API updates |
| `Coin` type | Now from `chia` umbrella crate |
| `Bytes32` | Import path changes |
| `singleton_top_layer_v1_1` | May move or rename |

### Verification Strategy

```bash
# 1. Update Cargo.toml with new versions
# 2. Run cargo check to find all type mismatches
cargo check 2>&1 | grep "error"
# 3. Fix each mismatch (mostly import path changes)
# 4. Verify tests still compile
cargo check --tests
# 5. Run existing tests to verify no behavioral changes
cargo test
```

### Type Interoperability

After alignment, these types MUST be the same across all crates:

| Type | Used In |
|------|---------|
| `Coin` | chia-query returns, chia-wallet-sdk consumes, our puzzles use |
| `Bytes32` | Everywhere — puzzle hashes, coin IDs, roots |
| `SpendBundle` | chia-query push_tx, our driver output |
| `PublicKey` | BLS pubkeys across prover and puzzle drivers |
| `CoinSpend` | chia-query returns, our drivers produce |

If types differ across crate versions, the compiler will emit E0308 (type
mismatch) errors. Fix by ensuring all crates use the same version of the
underlying type crate.
